# Seven-day commercial sprint

## Day 0 — started
- competitor research
- product brief
- working name BenchRoute
- dedicated commercial Git branch/worktree
- separate commercial Supabase decision
- pricing hypotheses
- security gap review
- responsive UI prototype

## Day 1 — tenant foundation
- dedicated Supabase beta project
- port required ERA tables/functions only
- fix and test tenant RLS
- add shop settings, plans, subscriptions, invites, usage
- seed demo tenant
- automated cross-tenant tests

## Day 2 — onboarding
- signup
- create shop
- trial entitlement
- business setup wizard
- invite staff
- default workflow/status templates
- first repair wizard

## Day 3 — core repair journey
- repair queue/workboard
- customer/item history
- bench notes and measurements
- attachments/photos
- quotes and approval
- parts usage
- ready/collection workflow

## Day 4 — customer and money
- branded customer tracker
- email templates
- invoices/receipts
- Stripe subscriptions
- Stripe customer portal
- optional payment links
- cancellation/grace period

## Day 5 — import/export and controls
- CSV import preview
- full tenant export
- audit viewer
- roles/permissions
- retention settings
- backup/restore rehearsal

## Day 6 — polish
- mobile QA
- desktop QA
- accessibility
- empty/error/loading states
- PWA install/update
- first-run help
- performance pass

## Day 7 — private beta
- landing page
- pricing page
- demo account
- onboarding docs
- support workflow
- invite 3–5 independent repair shops
- activation/retention metrics

## Beta definition of done
A shop owner can self-sign-up, configure shop, invite staff, receive an enquiry, convert it to a repair, diagnose/quote, get customer approval, record parts/notes/measurements, complete/invoice, provide tracking, export data, and start/cancel a subscription safely.
